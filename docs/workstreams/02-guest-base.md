# 02: Guest base image

Milestone: M1. Owns `interfaces/guest-conventions.md`. Consumes
`interfaces/vsock-guestd.md` (guestd is installed and enabled here, built by
04). Consumed by 03-hostd (builds and runs the output), 07-cli (relies on
every convention), 12-nix-config-pipeline (composes the user fragment on top
of this module).

## 1. Goal

Define the NixOS module every guest gets regardless of user config, and the
microvm.nix wiring that turns a NixOS configuration into a Cloud Hypervisor
runner using the host's shared store. Everything in
`interfaces/guest-conventions.md` and `DESIGN.md` §5 is produced here.

- `nix/guest/base/users.nix`: `dev` uid 1000, gid 1000, groups `wheel docker
  kvm`, home `/home/dev`, shell bash, `security.sudo.wheelNeedsPassword =

- `nix/guest/base/ssh.nix`: openssh with the settings in
  `interfaces/ssh-gateway.md`; host key generated by hostd at create and

  collide with `10.64.0.0/12`; `dev` in `docker`; `docker compose` plugin.
- `nix/guest/base/tmux.nix`: system tmux config at `/etc/tmux.conf` with
  the settings in guest-conventions (`set -g set-clipboard on`, `mouse on`,

  `repose-tmux-session.service` (user unit for `dev`, started at boot via
  `loginctl enable-linger dev`) that creates the session named after the
  slug from `project.json`. guestd's `SetupProject` is what writes
  `project.json` first; the unit waits on a path unit for that file.
- `nix/guest/base/agents.nix`: installs the five agents from
  `nix/overlay/agents/` (overlay in `nix/overlay/agents/default.nix`,
  wrappers in `nix/overlay/agents/wrap.nix`) plus `repose-hook`. Also
  registers Claude Code's hooks by writing `/etc/repose/claude-settings.json`
  and having the wrapper merge it into `~/.claude/settings.json` on first
  run if the hooks are absent (never overwriting user hooks).
- `nix/guest/base/browser.nix`: `chromium`, `playwright-driver.browsers`
  (chromium preset), `PLAYWRIGHT_BROWSERS_PATH` and
  `PLAYWRIGHT_SKIP_VALIDATE_HOST_REQUIREMENTS=1` in the environment;
  `@playwright/mcp` and `chrome-devtools-mcp` packaged in the overlay (they
  are npm packages; packaged with `buildNpmPackage`, pinned) and registered
  in `/etc/repose/mcp.json`, which the Claude wrapper merges into the
  user-scope MCP config on first run with `--headless` flags. Fonts:
  `noto-fonts`, `noto-fonts-color-emoji`, `liberation_ttf`, fontconfig
  enabled so screenshots render text.
- `nix/guest/base/desktop.nix`: `xorg.xorgserver` with Xvfb, `openbox`,
  `x11vnc`, `novnc`, `websockify`, as three socket-activated systemd
  services (`repose-xvfb.service` on `:99`, `repose-x11vnc.service` on
  `127.0.0.1:5900`, `repose-novnc.socket` on `127.0.0.1:6080`); connecting
  to 6080 starts the chain; a `repose-desktop-idle.timer` stops them after
  30 minutes with no websockify client. `DISPLAY=:99` is exported to
  shells only when Xvfb is running (a profile snippet checks the socket).
- `nix/guest/base/sysctl.nix`: `fs.inotify.max_user_watches = 1048576`,
  `fs.inotify.max_user_instances = 1024`, `fs.file-max = 2097152`,
  `net.core.somaxconn = 4096`, `vm.swappiness = 10`, and a 2 GB zram swap
  (`zramSwap.enable`) so a build that briefly exceeds RAM degrades rather
  than OOM-kills the agent.
- `nix/guest/base/env.nix`: `environment.variables` `LANG = "C.UTF-8"`,
  `EDITOR = "nvim"`, `REPOSE = "1"`, `COLORTERM = "truecolor"`; `TZ` and
  `REPOSE_PROJECT` come from `/etc/repose/env` written by guestd at
  `SetupProject` and sourced by `/etc/profile.d/repose.sh` together with
  `/run/repose/secrets.env`. `PATH` additions per guest-conventions.
- `nix/guest/base/guestd.nix`: `systemd.services.guestd` (root,
  `Restart=always`, `Before=sshd.service`, `WantedBy=multi-user.target`),
  binary from the flake's `packages.guestd` (04); creates `/run/repose`
  (tmpfs, 0755), `/run/repose/secrets` (tmpfs, 0700 dev), the hooks
  socket directory. Not ordered after `docker.service`: Docker starts in
  parallel and nothing on the path to the first login waits for it
  (DECISIONS I-161).
- `nix/guest/base/version.nix`: writes `/etc/repose/base-version` from a
  module option `repose.baseVersion` set by the flake from `git describe`
  of `nix/`, and `system.nixos.label` the same, so `nixos-version` inside
  the guest and `base_version` in the api agree.
- `nix/guest/base/network.nix`: systemd-networkd, one interface `eth0`
  matching the virtio MAC, static address from the kernel command line
  (`ip=10.64.x.y::10.64.x.1:255.255.252.0::eth0:off` set by hostd in the
  runner), DNS `1.1.1.1 8.8.8.8` (guests cannot reach the host, so no host
  resolver), `networking.firewall.enable = false` (the host enforces policy;
  a guest firewall would only confuse `repose open`).
- `nix/guest/base/boot.nix`: `boot.kernelPackages` = latest LTS from
  nixpkgs, `boot.kernelModules = [ "overlay" "br_netfilter" "nf_tables"
  "vsock" "vmw_vsock_virtio_transport" "virtiofs" ]`, `boot.initrd.
  availableKernelModules` = `virtio_pci virtio_blk virtio_net virtiofs`,
  no bootloader (CH direct kernel boot), `boot.loader.grub.enable = false`.
  The kernel line names the serial console's terminal and size
  (`systemd.tty.{term,rows,columns}.console`) and the initrd's services
  import no credentials, which removes about 1.7 s of timeouts and a
  mount rate limit from every boot (DECISIONS I-161).
- `nix/guest/microvm.nix`: a function `mkGuestRunner { fragmentModule,
  class, baseVersion, extraModules, ... }` that evaluates `nixosSystem`
  with `microvm.nix`'s module, home-manager, `guestBase`, and the fragment
  (applied to `dev` with `useGlobalPkgs` and `useUserPackages`), and
  returns a runner package whose `bin/run` takes every per-guest value as
  an argument (guest id, ip, gateway, cid, volume device, tap, mac, vcpu,
  memory, socket paths; DECISIONS I-34, contract in
  `interfaces/guest-conventions.md` "Runner contract"). The documented
  attributes `guestId, ip, gatewayIp, cid, volumeDevice, vcpu, mem,
  extraKernelParams` are still accepted as defaults for that script.
  microvm settings on the guest side: `hypervisor = "cloud-hypervisor"`,
  `shares = [{ tag = "ro-store"; source = "/nix/store"; mountPoint =
  "/nix/.ro-store"; proto = "virtiofs"; }]`, `volumes = [{ mountPoint =
  "/"; fsType = "ext4"; }]` (the first virtio disk), `writableStoreOverlay
  = "/nix/.rw-store"`, `microvm.storeOnDisk = false` (the store is the
  share, never copied into the image). The kernel line gets `console=ttyS0`
  and `ip=<ip>::<gateway>:<netmask>:<hostname>:eth0:off`, applied by
  systemd-network-generator. `share/repose/system` is
  `config.system.build.toplevel` so hostd can compare `kernel` and `initrd`
  between revisions (`kernel_changed`).
- `nix/guest/tests/`: NixOS VM tests (QEMU in CI, not CH) for: dev user and
  sudo, sshd accepts a CA-signed cert with the right principal and rejects
  the wrong one, docker runs `hello-world` with overlay2, tmux session is
  created from a fixture `project.json`, `repose-hook` posts to a fake
  socket, hooks are merged into a fixture `~/.claude/settings.json` without
  clobbering an existing hook, inotify sysctls applied, noVNC socket
  activation starts Xvfb, `repose-desktop-idle` stops it.

## 5. Design detail

### The shared store and the overlay

The guest mounts the host's export read-only at `/nix/.ro-store` and an
overlay with the writable upper dir on the thin volume at `/nix/.rw-store`,
presenting `/nix/store` as the union. microvm.nix's `writableStoreOverlay`
does this. The guest can therefore run `nix-shell` and `nix profile install`
for things not in the host store; those go to the overlay and are the
guest's own (and count toward its volume). The guest's `nix-daemon` runs
with `substituters` = cache.nixos.org only, `sandbox = true`, and cannot see
the host daemon. It builds inside its own vCPU and RAM caps, so a user
running a heavy `nix build` in a shell affects only themselves. This is
distinct from the config pipeline (12), where the host builds the system.

Consequence: a path the host garbage-collects while a guest overlay refers
to it breaks that guest. hostd roots every guest's system closure (01, 03),
and anything the user installed into the overlay is either in the overlay's
upper dir (safe) or a host path referenced by a guest profile. The second
case is closed by having the guest's `nix-daemon` copy any host path it
references into the overlay on install (`nix.settings.auto-optimise-store =
false`, and a guest-side `repose-pin-profile` activation hook that runs
`nix copy --to local?root=/nix/.rw-store` for the profile closure). The VM
test covers this: install a package into the profile, delete it from the
"host" store, the profile still runs.

### Why the fragment is home-manager, and where it lands

The base is a NixOS module; the user's fragment is a home-manager module
applied to `dev` through `home-manager.nixosModules.home-manager` with
`useGlobalPkgs = true` and `useUserPackages = true`. The fragment cannot
touch system services, users, networking, kernel or sshd because it is a
home-manager module, and the platform's `nixosSystem` call passes it only
there. Users who need a system service (Postgres, Redis) get it from the
menu catalog (12), which renders to a platform-controlled NixOS snippet
with an allowlist of services. That boundary is what makes "user Nix on a
shared host" defensible: the fragment can install anything into the home
profile and nothing outside it.

### The ssh host key is a secret

The guest's host key must be stable across restarts (or the CLI's
known_hosts would churn) and signed by the Host CA. hostd generates it at
`CreateGuest`, asks the api to sign it, and delivers both through the
secrets tmpfs mechanism with the reserved names `ssh_host_ed25519_key` and
`ssh_host_ed25519_key-cert.pub`. An activation script symlinks them into
`/etc/ssh/`. Reserved names are rejected by `PUT /secrets` (05).

### Agent wrappers and hooks

`wrap.nix` produces, for each agent, a script that sets `TERM`, `COLORTERM`,
merges platform hook config on first run, and execs the real binary with
`"$@"`. The merge is a `jq` deep merge that adds the `repose-hook` entries
under `hooks.Notification` and `hooks.Stop` (Claude Code) only if no entry
with `repose-hook` in its command exists. For agents without a hook system
(pi, and opencode until it has one), guestd's `AgentState` heuristic (tmux
pane idle with the agent process alive and the last line ending in a prompt
marker) produces `needs_input` and `completed` events; `features/agents.md`
documents per-agent accuracy.

### noVNC chain

Socket activation keeps the desktop's memory cost at zero until asked.
`repose open --desktop` forwards 6080; the browser connects; systemd
starts a `systemd-socket-proxyd` service that requires websockify, which
pulls in x11vnc, which pulls in Xvfb and openbox (DECISIONS I-33).
Chromium launched by the agent with `DISPLAY=:99` (the profile snippet
exports it when Xvfb is up) appears on that desktop. When the agent runs
headless Chromium, nothing is displayed and nothing is started.

### Docker address pools

Docker's default `172.17.0.0/16` and the compose pools would not collide
with `10.64.0.0/12` today, but a user's compose file with `10.64.x.x` would.
Pinning `default-address-pools` to `172.20.0.0/14` makes the collision
impossible rather than unlikely.

### Retiring `packages/core/flake.nix`

The current dev box runs from that flake with `home-manager switch`. After
`tools.nix` exists: (1) `nix/flake.nix` exposes `devShells.default` with the
same tools; (2) the dev box switches to it; (3) `packages/core/` is deleted
and `pnpm-workspace.yaml` no longer lists it. Until (2) is confirmed on the
dev box, the flake stays.

## 6. Failure modes

| Failure | Outcome |
|---|---|
| Guest boots but sshd refuses the certificate | `AuthorizedPrincipalsFile` missing or wrong principal. guestd's `SetPrincipals` writes it; if guestd never ran, `Ready` was never sent and the api shows the guest as `starting`, then `error` after 120 s with `guest did not become ready`. The console log (hostd) shows the sshd error. |
| `/nix/store` union missing paths | virtiofs share not mounted or wrong tag. Guest journal: `mount: /nix/.ro-store: wrong fs type`. hostd reports `guest_unresponsive` after Ping fails; console log has the mount error. |
| Docker fails with `overlay2 not supported` | Kernel module list wrong or the volume is not ext4. VM test catches it; in production it is a base bug, guests are not affected until they are switched to the new base, and `hold_base_updates` exists for this. |
| Agent wrapper clobbers a user hook | Forbidden by the merge rule; VM test asserts an existing hook survives. |
| Xvfb starts but Chromium shows nothing | `DISPLAY` not exported because the profile snippet ran before Xvfb. The snippet checks the X socket each shell start; the user opens a new shell. Documented in `features/browser.md`. |
| A user profile references a host path that gets collected | `repose-pin-profile` copies profile closures into the overlay; if it did not run (activation failed), the error is `nix: path /nix/store/... does not exist` in the guest; the fix is `nix profile install` again, and the base bug is filed. |
| Guest OOM | zram absorbs bursts; the kernel OOM killer picks the largest process, which is usually a build, not the agent. guestd sends `Warning{kind: "oom"}` from `dmesg`, and the user sees it in `repose status`. |

## 7. Testing

- `nix flake check` runs `nix/guest/tests/` on QEMU with a fake shared
  store (a squashfs of the closure mounted read-only at `/nix/.ro-store`)
  so the overlay logic is tested without CH.
- On a real host with 03: create a guest with the base and no fragment,
  run every command in the checklist from inside it.
- Size: the base closure must be under 6 GB (checked in CI with `nix
  path-info -S`); a bigger base means every host's store grows and every
  first-boot copy of the closure metadata takes longer. Fail the check
  above 6 GB and record the offender.

## 8. Rollback

A bad base version is rolled back by re-applying the previous
`base_versions` row: the api sends `ApplyConfig` with the previous closure
(still rooted for 14 days) to every guest not on hold. The base bump job
(12) records the previous version so this is one admin command:
`repose-admin base rollback <version>`.
