# The control plane as one Coolify resource

`docker-compose.yml` here is the whole control plane on the control VM:
Postgres, the HTTP api, the gRPC api, the dashboard, and the nightly backup
to R2. Coolify deploys it as a **Docker Compose** resource from this
repository (DECISIONS I-87), so everything about the deployment is a file
except the values that are secrets and the two domains, which Coolify
holds. `docs/ops/coolify.md` is the order of operations around it.

## Creating the resource

Project -> Add resource -> Docker Compose -> Git (public or via the GitHub
app): repository `heracraft/repose`, branch `main`, base directory `/`,
Docker Compose location `/ops/coolify/docker-compose.yml`, server the
control VM. Coolify reads the file and lists every `${VAR}` under
Environment; the ones written `${VAR:?}` block the deploy until set.

## Domains

Two services are public, both behind the proxy Coolify runs on the server:

| service | Domains field                              |
| ------- | ------------------------------------------ |
| `api`   | `https://api.repose.herakraft.co:8080`     |
| `web`   | `https://repose.herakraft.co:3000`         |

The port is the container port; the public side is 443, with a Let's
Encrypt certificate the proxy obtains itself (80 and 443 are open).

## Values to set

Required (the deploy refuses without them):

| variable | where it comes from |
| --- | --- |
| `LOGTO_M2M_CLIENT_ID`, `LOGTO_M2M_CLIENT_SECRET` | the `repose-api` M2M application in Logto (`accounts.herakraft.co`), role with Management API access |
| `PUBLIC_LOGTO_APP_ID` | the `repose-web` SPA application in Logto |
| `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET` | the api's Entra app registration (`docs/ops/AZURE-SETUP.md`); its object id also goes in `api_identity_object_id` for the Key Vault policy |
| `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_ENDPOINT` | the R2 API token (DECISIONS I-21); `tofu -chdir=infra/r2 output coolify_s3_destination` prints the endpoint, with its `https://` |

Optional, with working defaults in the file: `LOGTO_ISSUER`,
`API_RESOURCE`, `KEYVAULT_*`, `BLOB_*`, `GATEWAY_*`, `DASHBOARD_URL`,
`NOTIFY_FROM`, `LOG_LEVEL`, `BACKUP_HOUR_UTC`, `BACKUP_KEEP_DAYS`,
`R2_BUCKET`, `GRPC_SERVER_NAMES`. Empty until the feature is turned on:
`RESEND_API_KEY` (notifications), `STRIPE_*` and
`PUBLIC_STRIPE_PUBLISHABLE_KEY` (billing; empty means `503
billing_disabled` and usage still accrues), `OTEL_EXPORTER_OTLP_ENDPOINT`.

`SERVICE_PASSWORD_POSTGRES` and the two `SERVICE_FQDN_*` are generated by
Coolify; leave them.

## Ports on the VM

`api-grpc` publishes 8443 (hostd) and 8444 (the gateway's `/internal`),
and both apis publish their metrics (9103, 9104). None of these are open on
the public IP: the control NSG allows 22, 80 and 443 only, and hosts, the
edge and Prometheus reach them over WireGuard at the VM's `10.255.255.1`
(`infra/README.md`, "Wiring the control plane to the edge"). hostd is
registered with `apiAddr = 10.255.255.1:8443` and
`apiServerName = api.repose.herakraft.co`, the first of
`GRPC_SERVER_NAMES`, because the gRPC certificate is issued for that name
from the api's own CA at start (I-87).

## Deploys

A push to `main` (or the Redeploy button) rebuilds the two images from the
Dockerfiles and recreates the services that changed. `api` runs the
migrations before it serves (`-migrate`), and `api-grpc` waits for `api`
to be healthy, so a new image never serves against an old schema. A compose
deploy is not a rolling deploy: the api and dashboard are down for the
seconds it takes the new containers to pass their health checks. That is
accepted until launch; the file-per-resource shape is worth more now than
zero-downtime deploys, and moving `api` and `web` to Coolify "Dockerfile"
applications later is a UI change, not a code change.

## Backups

`pg-backup` writes a `pg_dump -Fc` into the `pgbackups` volume nightly at
`BACKUP_HOUR_UTC` and prunes local copies after `BACKUP_KEEP_DAYS`;
`backup-sync` copies new dumps to the R2 bucket every 15 minutes and never
deletes there. Verify with `ssh root@<control ip> repose-backup-check`
(needs the `r2` rclone remote on the VM, once, from the same token). A
manual dump: in Coolify's terminal for `pg-backup`, `pg-backup once`. The
restore procedure is `docs/ops/RUNBOOK.md` "Postgres restore".
